# Preview System Enhancement Plan

## Overview
Enhance the existing preview system with robust error handling, progressive rendering, intelligent auto-fixing, and user feedback collection.

## Current State Analysis
Based on exploration of [app/api/preview-code/route.ts](app/api/preview-code/route.ts):
- Multi-file support already implemented (hooks, utils, components)
- Basic error handling with Babel compilation and 3 retry attempts
- Pattern-based auto-fix in [lib/code-auto-fix.ts](lib/code-auto-fix.ts) (40+ patterns)
- HTML entity decoding and import resolution working
- Component-level error placeholders exist

## Implementation Plan

### 1. Error Handler Module

#### 1.1 Syntax Checker (Pre-compilation)
**File**: `lib/syntax-checker.ts` (new)
- Add ESLint-like validation before Babel compilation
- Check for common syntax errors: unclosed brackets, missing semicolons, invalid JSX
- Return structured error objects with line numbers and suggestions
- Integration point: [route.ts:985](app/api/preview-code/route.ts#L985) before Babel transform

#### 1.2 Runtime Monitor
**File**: Modify [route.ts:1500-1600](app/api/preview-code/route.ts#L1500-L1600) HTML template
- Add error boundary wrapper in generated HTML
- Capture console.error and runtime exceptions
- Display runtime errors in UI with stack traces
- Add error event listener: `window.addEventListener('error', handler)`

#### 1.3 Dependency Resolver
**File**: Enhance [route.ts:938-983](app/api/preview-code/route.ts#L938-L983)
- Build dependency graph for components/hooks/utils
- Detect circular dependencies
- Validate all imports resolve to defined modules
- Warn about missing dependencies before compilation

### 2. Progressive Renderer Module

#### 2.1 Component Isolator
**File**: Modify [route.ts:1520-1540](app/api/preview-code/route.ts#L1520-L1540) script injection
- Wrap each component in try-catch during registration
- Create isolated error boundaries per component
- Allow partial rendering when some components fail
- Implementation: Modify `window.ComponentName = ...` registration

#### 2.2 Fallback Renderer
**File**: Enhance [route.ts:925](app/api/preview-code/route.ts#L925) error placeholder
- Improve error placeholder styling with actionable messages
- Show "View Error Details" expandable section
- Display suggested fixes from auto-fix system
- Add "Retry" button for failed components

#### 2.3 State Restorer
**File**: Add to HTML template [route.ts:1500+](app/api/preview-code/route.ts#L1500)
- Implement localStorage-based state persistence
- Save component state before re-render
- Restore state after hot-reload or error recovery
- Add `window.__PREVIEW_STATE__` global object

### 3. Smart Fixer Module

#### 3.1 Auto Completer
**File**: Enhance [lib/code-auto-fix.ts:307-377](lib/code-auto-fix.ts#L307-L377)
- Add AST-based tag completion (not just regex)
- Detect incomplete JSX structures using Babel parser
- Auto-complete missing imports based on usage
- Suggest missing props for components

#### 3.2 Pattern Matcher
**File**: New `lib/error-patterns.ts`
- Centralize error pattern definitions
- Map Babel errors to fix strategies
- Add confidence scores for each fix
- Support multiple fix suggestions per error

#### 3.3 AI Assisted Fix
**File**: New `lib/ai-fix-suggester.ts`
- Integration with generate-async API for complex fixes
- Send error context + surrounding code to AI
- Request targeted fix (not full regeneration)
- Apply AI suggestion with user confirmation

### 4. User Feedback Loop Module

#### 4.1 Error Collector
**File**: New `app/api/preview-errors/route.ts`
- POST endpoint to collect error reports
- Store: error type, code snippet, fix applied, success rate
- Database schema: `preview_errors` table
- Rate limiting: max 10 reports per session

#### 4.2 Issue Classifier
**File**: New `lib/error-classifier.ts`
- Categorize errors: syntax, runtime, dependency, type
- Assign severity: critical (blocks render), warning (partial), info
- Track error frequency and patterns
- Generate weekly error reports

#### 4.3 Improvement Suggester
**File**: Enhance [route.ts:1050](app/api/preview-code/route.ts#L1050) response
- Include "Common Issues" section in error response
- Suggest preventive measures based on error history
- Link to documentation for frequent errors
- Show success rate of auto-fixes

## Performance Considerations

- Syntax checking adds ~50-100ms per file (acceptable)
- Error boundaries have minimal runtime overhead
- State persistence uses localStorage (fast)
- Error collection is async (non-blocking)
- AI-assisted fix is opt-in (user-triggered)

## Rollback Strategy

- Feature flags for each module (can disable independently)
- Graceful degradation if new features fail
- Preserve existing error handling as fallback
- Database migrations are reversible

## Success Metrics

- Reduce preview failures by 50%
- Increase auto-fix success rate from 60% to 85%
- Collect 1000+ error samples for analysis
- User satisfaction score > 4.0/5.0
- Average error resolution time < 30 seconds
